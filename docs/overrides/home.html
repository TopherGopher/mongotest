Go · MongoDB · Docker or Podman

A real MongoDB
for every Go test.

mongotest starts a MongoDB container for a Go test, hands you a connection to it, and removes it when you call KillMongoContainer. Each test gets an empty server of its own.

Why mongotest

Test against the database you ship with

Each test gets a real mongod of its own, so there is no mock to keep in step and no data shared between tests.

{% include ".icons/material/shield-check-outline.svg" %}

One server per test

Every test starts with an empty server, so parallel tests cannot see each other's data.

{% include ".icons/material/broom.svg" %}

Cleanup that survives Ctrl+C

t.Cleanup removes the container, a signal handler removes it if the run is interrupted, and a label finds anything left.

{% include ".icons/material/swap-horizontal.svg" %}

The official driver, or easymongo

conn.MongoDriverClient() returns the official *mongo.Client. The connection also embeds easymongo.

{% include ".icons/material/source-branch.svg" %}

Replica sets, scripts, exports

A single-member replica set for transactions and change streams, commands inside the container, and fixtures exported as JSON.

{% include ".icons/simple/podman.svg" %}

Docker or Podman

Speaks the Engine API, never the CLI, so Podman's Docker-compatible socket works too. Point DOCKER_HOST at it.

How it works

From one call to a running server

  1. 1

    Find the daemon

    Through DOCKER_HOST, or the default socket. Over HTTP; the docker binary is never run.

  2. 2

    Pick a port, start a container

    A free loopback port from the kernel, a container named mongo-<port> and labelled mongotest=regression. The image is pulled on the first run only.

  3. 3

    Connect and wait

    A direct connection to 127.0.0.1:<port>, pinged with a short backoff until mongod answers.

  4. 4

    Remove

    KillMongoContainer force-removes the container and its volumes. Register it with t.Cleanup and it runs whether the test passes or fails.

What is in the module

The packages

Tests import mongotest. The Docker client packages underneath are public and can be used on their own.

mongotest

The test helpers

NewTestConnection, the one-shot helpers, replica sets, scripts and the exporter.

 mongod landing

The container, no driver

Start a container and get its URI, with no MongoDB driver imported. In PR #53.

 dockerclient

The interface

The interface every Docker client here implements, with its types and errors.

 dockerapi

The default client

Standard library only. Finds the daemon as the docker CLI does, and works with Podman.

 mobyclient

The official client, wrapped

A separate module for projects that already depend on moby/moby/client.

 dockermock

The test doubles

Mock records calls, Fake is a daemon in memory, Daemon is one over HTTP.
