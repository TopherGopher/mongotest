Why mongotest

Test against the database you ship with

Mocks drift. Shared databases leak state. A real mongod that exists for exactly one test does neither.

{% include ".icons/material/shield-check-outline.svg" %}

Complete isolation

Every test starts with an empty server and ends with no server. Parallel tests cannot see each other, and a crash in one cannot poison the next.

{% include ".icons/material/timer-outline.svg" %}

About a second to start

On a warm image cache a container is pinged and ready in roughly a second, and parallel tests overlap those seconds.

{% include ".icons/material/broom.svg" %}

Four layers of cleanup

t.Cleanup, a signal handler for Ctrl+C, a finalizer, and a label on every container so strays are one command away.

{% include ".icons/material/swap-horizontal.svg" %}

Your driver, your call

Use the embedded easymongo connection, or ask for the official *mongo.Client and never touch easymongo at all.

{% include ".icons/material/source-branch.svg" %}

Replica sets, scripts, exports

A single-member replica set for transactions and change streams, commands inside the container, and fixtures exported as JSON.

{% include ".icons/simple/podman.svg" %}

Docker or Podman

Speaks the Engine API directly, never the CLI. The standard-library client negotiates versions and finds Podman's socket on its own.

How it works

From one call to a running server

  1. 1

    Find the daemon

    Through DOCKER_HOST, the current Docker context, or the default socket. Over HTTP; the docker binary is never run.

  2. 2

    Pick a port, start a container

    A free loopback port from the kernel, a container named mongo-<port> and labelled mongotest=regression. The image is pulled on the first run only.

  3. 3

    Connect and wait

    A direct connection to 127.0.0.1:<port>, pinged with a short backoff until mongod answers. Then the connection is yours.

  4. 4

    Remove

    KillMongoContainer force-removes the container and its volumes. Pass or fail, nothing is left behind.

What is in the module

One import for tests. A toolkit underneath.

The Docker layer is public and useful on its own: an interface, two implementations and a set of test doubles that all pass the same conformance suite.

mongotest

The test helpers

NewTestConnection, the one-shot helpers, replica sets, scripts and the exporter.

 dockerclient

The interface

Thirteen methods, the shared types and the error sentinels. Standard library only.

 dockerapi

The default client

Zero dependencies. Daemon discovery, version negotiation, Podman detection.

 mobyclient

The official client, wrapped

A separate module for projects that already depend on moby/moby/client.

 dockermock

The test doubles

Mock records calls, Fake is a daemon in memory, Daemon is one over HTTP.
